# Effect lesson to independently rebuilt skill

Use this procedure for an authorized end-to-end recreation or effect lesson. An
analysis-only request stops at analysis; a prototype-only request stops at the
reviewable prototype. Record the requested stopping point before starting. These
are agent instructions using existing tools, not a new service or API.

## 1. Freeze the task and evidence boundary

Preserve the initial brief, reference hashes/windows, creator marks, locked choices,
raw/prepared input boundary and the applicable contracts in a private lesson receipt.
Read the source-linked reference record and record missing evidence explicitly.
Use the effect brief and timing map from the parent skill. For each acceptance item
name its evidence source, observable condition and tolerance before construction.
Unknown tolerance is unresolved; choose and disclose a bounded assumption only when
it cannot materially change the intended effect.

Before dispatch, resolve any acceptance condition whose required precision cannot
be supported by its source evidence. Invoke the owning craft method's ambiguity
gate: for a clean-plate gesture reveal, follow video-compositing's clean-plate
object-reveal procedure and obtain the creator's reveal mark or clearer gesture
cue. A silent blurred gesture does not license an invented completion frame. If
missing guidance prevents certification, retain causal timing as unverified and
request that specific input; do not rerun unchanged builds to manufacture certainty.

Include causal relationships, not just matching event order: what triggers each
appearance, clone, freeze, reveal, scene switch or sound; which actor owns it;
source-time versus timeline-time mapping; exact boundary frames/PTS, hold lengths,
entrance/exit durations and overlap. For example, “a copy appears on the first frame
after the subject leaves the marked stopped pose” must be checked at that boundary,
not replaced with “copies appear in order.” Preserve any user-specified numerical
requirement exactly. Record allowed adaptations separately from observed reference
behavior. A changed creative requirement creates a versioned acceptance revision. Regrade
only its affected criteria against that direction, preserving original measurements
and applicable evidence. A creator-accepted slight alignment difference does not
require a rebuild solely to meet a superseded default; it does not excuse a missing
effect component. Use reference-match-review's completeness versus precision split.

Set a task budget before dispatch: by default at most three fresh rebuild attempts
and two diagnostic repair rounds, with a declared wall-time budget appropriate to
input length and preparation. User-specified budgets win. Stop identical deterministic
failures until their cause changes. Exhaustion leaves a partial result with the next
needed action; it never implies success or authorizes extra spend.

## 2. Build and correct the editable prototype

Intake/prepare sources through the existing media skills and MCP surface. Inspect
existing templates, presets and compiled routes before composing or developing.
Build the prototype with the applicable craft skill, bounded assembly/proposal
contracts and controls. Preserve source identity, continuous-source authority and
meaningful actor editability. Check each mutation result before issuing dependent
calls: a fulfilled tool transport can still return `isError: true`. On an error or
unknown state change, inspect the timeline before retrying; do not continue lane
ordering or handoff from assumed element creation. Resume from confirmed elements
using the current supported tool contract. Hand off assemblies before presenting them.

Capture the creator's corrections as project feedback when applicable, link proposal
revisions and retain accepted choices. Human correction and approval are distinct:
never apply a proposal merely because the creator explained the desired change.
Classify failures before repairing: unclear method goes in the owning craft skill;
missing preparation goes in its input/preparation contract; real schema, rendering,
control or tool defects go to their deterministic owner with required checks.
Search the catalog and implementation first: a tool that exists but was missed is
a discovery/invocation problem. Follow tool-authoring and agent/harness contracts
for actual tool or runner changes. Do not describe an unavailable capability into
existence or introduce a parallel editing architecture.

For unavailable native capability, follow the parent skill's report/disposition step:
file `capability_gap_report`, retain its receipt and failing case, and honor explicit
creator deferrals. A learning-service repair queue does not authorize the effect
worker to bypass a deferred gap or claim that reporting fixed it. If the creator
subsequently authorizes repair, supersede that disposition, fix its native owner and
rerun the original blocked supplied-input case through the remaining gates. Carry
its receipt through implementation and effect validation; a queue assignment alone
is not completion.

When widening a native parameter range, test its runtime consumers as well as schema
and export: navigate keyframes, change the value, seek, play, reload and restore the
baseline in a disposable copy. Include muted and audible media paths where relevant.
A successful high-speed export does not prove that an audio-preview component can
accept that rate. Keep the source clock authoritative; skip unsupported muted native
playback safely, and surface unsupported audible rates explicitly rather than
silently clamping them. Record the original failing interaction and its passing
retest before closing the capability gap.

## 3. Save the method before testing it

Solidify the effect's owning craft skill and card: declared asset roles and constraints,
preparation, supported construction route, meaningful controls, causal timing,
verification and recovery. Keep substantial detail in its references and record the
change in its evolution log. Link canonical contracts instead of copying them.
Check frontmatter, links and discovery through skill-authoring. A saved file is not
proof the installed catalog serves it: record fetched version/hash or the
exact discovery failure. Do not publish or upload to repair discovery without authority.

Freeze the tested package version. The second build is mandatory for an end-to-end
lesson even if the first prototype looks correct. The saved procedure must carry the
reusable learning; private coaching cannot substitute for it.

## 4. Start the second build without history

Use a fresh builder session with no authoring conversation, on the strongest model your
agent offers (or the one the creator names); record which model and run ID built it.

Give the builder only the saved skill/card and their linked contracts, declared
inputs and the initial creator brief/marks, the solution-free frozen acceptance
conditions/tolerances, and an input-only disposable project. The builder must know
the specification it will be judged against; withhold grader-only reference/output
measurements that reveal the previous solution, not the required precision.
Prepare a sanitized input-only dispatch copy/manifest of that package. Keep the
accepted timeline, previous proposal/output settings and media, diagnostic transcript
and solution-derived coordinates/times out, including values exposed by card demos,
linked receipts, evolution logs or example evidence. Retain generic procedures and
useful examples only when they do not encode this test solution. Record exact supplied
files/hashes and the previous-output roots excluded from the task; keep the full card
and prior result available to the grader, not the builder. This is a prompt/context
boundary, not a claim that an unrestricted coding agent cannot read other files.
Record access-trace coverage and any observed leakage; a run that consumes the previous
solution is invalid as a clean trial. Initial creator marks are valid inputs. The
builder must be able to access the actual bytes and modalities it needs; a path alone
is not evidence it inspected them. Use the parent skill's input-project preparation
and context-boundary instructions. The result is a second, separately identified
reviewable artifact, never a replay or copy of the first result.

A builder reports artifacts, tool failures and inspection gaps. Its self-assessment
cannot supply the acceptance verdict. A diagnostic session may see failures and help
repair; it does not count as the next fresh rebuild.

## 5. Grade the artifact independently

Use a separate grader session, on the strongest model available. It receives the frozen acceptance
sheet, references and provenance, declared inputs, resulting proposal/derived timeline,
GPU frame-state report and frames, normal-speed playback and applicable audio/control
evidence. It does not receive the builder's claimed pass as evidence. Give it actual
inspectable media; record any missing image, video or audio modality.

For every criterion return pass, fail or unverified, a concrete artifact/frame/time
reference, measured deviation where applicable, and severity. Inspect source/output
clock mapping and every causal boundary, with surrounding frames, as well as full
moving intervals. Judge visual fidelity, continuous source integrity, picture/sound
relationships, editability, controls and source preservation separately. Still images
cannot establish motion or sound. An advancing playhead plus an endpoint screenshot
proves playback progression, not continuous visual inspection or concealment through
the hidden interval. Record actual visually inspected frames/moving intervals and
keep uncovered required intervals unverified. Use frame-state discipline and
reference-match-review.
Run the existing effect-one-click grader for compiled routes; it supplements visual
and causal checks and cannot establish preparation accuracy or automatic timing discovery.

A required unverified item prevents a verified verdict. Never average away a critical
causal error with a score for appearance. Grading is independent evaluation, not human
approval and not permission to export. Obtain missing evidence through already
authorized inspection; any additional export still requires explicit authorization.

## 6. Repair the owner, then rebuild fresh

The author diagnoses each failed/unverified item from evidence, distinguishing method,
input, tool, renderer, harness/context and inspection failures. Update the responsible
skill/tool and its evolution record, run affected checks, and retain old/new versions
and the failure-to-fix mapping. Do not loosen frozen criteria, flatten editable actors,
remove useful controls or feed the prior solution to the next builder to gain a pass.

Within the remaining budget, dispatch another fresh builder with the revised saved
package and declared inputs, then independently grade the new artifact. Rerun all
checks affected by a repair; reuse unchanged evidence only for unchanged inputs,
dependencies and the same review question. Stop at a verified applicable pass, user
pause/scope change, budget exhaustion or a concrete unavailable prerequisite/authority.
Retain partial work, attempts and exact next action. Ordinary prototype corrections
must also respect the one-to-three-card pass and human-review boundaries.

## 7. Record reuse honestly and close the lesson

A second build on the same inputs establishes repeatability only. A separate fresh
input set establishes transfer only for the changed dimensions tested (take, subject,
count, duration or aspect ratio). Raw-source trials cover preparation and construction;
prepared-input trials cover construction only. Guided marks do not prove automatic
mark discovery. Keep each claim and its evidence separate. Shared complete/reusable
promotion still requires the parent skill's fresh-input acceptance; a same-input pass
alone cannot satisfy it.

Keep private inputs, result links, hashes, package/model versions, attempts, verdicts,
rights, modalities, controls and remaining limits in the lesson receipt. Route authorized personal
catalog/card packaging through effect-authoring's Yours contract and validate with
`userEffectRecipesSchema`; inspect the card and actual Input/Result in the editor.
An end-to-end request that includes personal packaging authorizes this work without
a second permission gate. A home-page template draft has its own creator-only Save
contract; preserve that boundary when using that route. Use existing authorized
demonstrations where valid; rendering a creator project still requires explicit
export authorization. Do not invent a catalog writer/API, change My Style, commit
private evidence or publish a contribution. Keep packaging partial if playable
demonstrations, applicable Save, authorization or verification remain pending.

For a full lesson request, close with session-retro on the recorded workflow (its
actual transcript and evidence): diagnose avoidable corrections/tool gaps, make
in-scope fixes in their owners and record deferred work. The retro never applies,
rejects or restores project edits. Report its cutoff if the session is still running.
The closeout lists prototype, saved package, independent rebuild verdict, transfer
status, private catalog/save status, retro and unresolved checks separately. Workflow
authoring or a written walkthrough is not an executed lesson or effect rebuild.
