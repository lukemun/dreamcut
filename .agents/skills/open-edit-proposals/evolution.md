# open-edit-proposals — evolution log

## Purpose
The mandatory path for agent edits to an existing working timeline: every agent change goes through a previewable proposal the human reviews, adjusts, approves, or rejects. Scope: inspection and mutation of timelines already on the working cut — inside a fresh assembly workspace, direct construction applies instead. The agent never approves or rejects. Good looks like: one independently reviewable beat per proposal; derived review rows computed from the patch (the agent authors rationale and chooses supported controls, never row descriptions); approval is atomic with before/after history snapshots. The first proposal supplies the working controls and useful ranges needed to reach the intended result, with likely adjustments prioritized and relevant secondary choices available. Success includes fewer follow-up requests and replacement proposals solely for missing dials, assessed with explicit audit-coverage limits.

  `20260928T152802-57e38adb` selects size, horizontal, vertical and entrance time.
  Existing blueprint controls did not expand into every fact label's coordinates.
  This validates the current transport and example, not future agent judgment.

## 2026-09-29 — First-proposal tuning coverage (Updated)

- **Observation:** The creator reports that proposal dials often do not match what
  they want to control. They requested an architectural goal of sufficient controls
  on the first proposal, a bias toward more relevant dials, main/advanced grouping,
  and auditing of the adjustments people make. Earlier minimal-subset language
  conflicted with that requested default.
- **Decision:** Make coverage the selection goal, connect each tuning need to a
  working control/range, and retain relevant secondary choices. The shared inspector
  standard owns tiering, current fallback, audit requirements and retrospective
  evaluation. Effect skills supply parameter meaning; the proposal skill owns
  intent-to-control selection across effects.
- **Verification:** Inspected the panel, approval persistence and retro input:
  final overrides are saved and included in retros; intermediate interactions are
  not durable. Main/advanced presentation and complete interaction auditing remain
  implementation work. Instruction walkthroughs cover placement (size/X/Y), a
  coordinated sequence (shared timing), and an unavailable group control (explicit
  capability gap). These checks do not prove improved future agent selection.

Skill-purpose and catalog checks passed (2 tests); documentation whitespace checks passed.

## 2026-10-02 — Reference and revision continuity (Updated)

- **Observation:** Partial reference extraction and rebuilding tuned drafts cause repeated corrections.
- **Decision:** Route full references through video-reference-analysis; bounded effects share its structured record. Proposal revisions use the saved tuned baseline and combined preview before handoff.
- **Verification:** Focused schema, proposal and tool checks exercise the new paths; no whole-session speedup or visual equivalence is claimed.
- **Observation (2026-10-10):** Activity-journal episodes of the 11-case feature eval showed GPT-6.1-Sol making 27 `proposal_spatial_preflight` calls across 33 runs, mostly for edits that cannot move anything (reverse, colour, volume), while Sonnet 5.5 skipped the required preflight on every visual edit.
- **Decision:** `proposal_create` now runs the scoped spatial check itself for every option that can move or cover something, stores `spatial_review` on the record and warns about introduced overlaps; `proposal_spatial_preflight` is an optional dry run for layout-heavy work. Step 5 reflects this.
- **Verification:** Both models 33/33 before and after. GPT: preflight calls 27 → 0, mean calls 8.7 → 7.6, mean time 20.1 s → 17.5 s. Sonnet unchanged (4.8 calls, ~13 s) and now always checked. The real check on a 135-element project costs ~55 ms. Focused route tests cover staging with and without the check.

  `http://127.0.0.1:3123/p/<project_id>` link in every reply that mentions a project or something to
  review, whether or not a browser pane was opened.
- **Verification:** Instruction change only; not yet measured on agent runs.
