# Windows pitfalls met so far

Each was found by these checks and fixed in shared code (2026-10-22). Look here first when a step fails.

| Symptom on Windows | Cause | Fix in place |
| --- | --- | --- |
| `spawnSync npm ENOENT`, `spawn EINVAL` | `npm`, `pnpm` and installed bins are `.cmd` shims; Node will not start them without a shell | Run the tool's JavaScript entry with `process.execPath`; for a shell use `cmd.exe /d /s /c` with quoted arguments |
| `ERR_UNSUPPORTED_ESM_URL_SCHEME ... protocol 'c:'` | An absolute Windows path passed where a module URL is expected | `pathToFileURL(path).href` |
| `Cannot find module '@swc/helpers/...'` when the editor starts | The Windows runtime is copied without links (extracting links needs a privilege), which breaks pnpm's linked layout | The isolated Windows build installs with `--config.node-linker=hoisted` ([desktop/build.mjs](../../../../desktop/build.mjs)) |
| The isolated install finishes instantly and `next` is missing | No `pnpm-workspace.yaml` in the isolated folder, so pnpm used the enclosing checkout | Copy `pnpm-workspace.yaml` and `patches/` into it |
| `ENOENT next-env.d.ts` on a fresh checkout | Git-ignored file generated by Next | Skip it when absent |
| A record left behind after the agent disconnects | Agent apps on Windows end servers with an immediate kill, which skips exit handlers | The MCP server stops its editor and exits when stdin closes |
| `mode & 0o777` checks fail | Windows has no POSIX mode bits (reports `0o666`) | Skip mode checks on `win32`; app data is user-private by ACL |
| `npm.ps1 cannot be loaded because running scripts is disabled` | PowerShell's default execution policy | `Set-ExecutionPolicy -Scope CurrentUser RemoteSigned`. The README's Windows install runs `pnpm` in PowerShell, so users on the default policy hit it (`pnpm.ps1`) |
| Adding an imported video returns 409 "Video is not ready. Prepare its preview…" | `path.relative` gives `sources\clip.mp4` on Windows; stored paths and preparation keys must match the forward-slash paths in media URLs | Store project-relative paths with `portableRelative` ([src/lib/local-store/paths.ts](../../../../src/lib/local-store/paths.ts)), never `path.relative` |
| Export stops near the end: FFmpeg `Server returned 403 Forbidden` for a `/api/projects/.../media/...` URL | The packaged editor refuses requests without its session cookie, and the audio mix handed media URLs straight to FFmpeg (not Windows-specific; the first packaged export with sound) | FFmpeg and FFprobe inputs send the cookie to this machine's editor only (`mediaInputArgs` in [src/lib/render/audio-export.ts](../../../../src/lib/render/audio-export.ts)) |
